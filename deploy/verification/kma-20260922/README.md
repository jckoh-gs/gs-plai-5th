# KMA 연결 검증

사용자가 제공한 API허브 인증키를 `gs-plai-5h/grid-kma` Secret의 `auth-key`에 등록하고 앱 환경변수로 연결했다. 키 값은 증거·소스·브라우저 구성에 기록하지 않았다. 현재 이미지는1.7.2/645a098 그대로이며 환경변수 적용을 위한 재시작만 수행했다.

실제 서버의 격리 객체 조회에서 기상청 HTTP200·관측 파싱 성공을 먼저 확인한 뒤 Secret을 등록했다. 이후 실제 UI에서 사용자 화면의 대관령 RTU에 KMA 조회를1회 수행하여 출처kma·오류없음·관측시각·실시간 표시를 확인했다. 인증된 브라우저 요청은 Kubernetes 암호화 터널을 통과했다. 기존6개 RTU 설정·run ID를 전후 해시로 대조했고 제어 명령은 보내지 않았다.

[summary.json](summary.json), [실제 UI 결과](browser-verification.json), [13개 관련 시험](tests.log)을 참조한다. 일사650W/m²는 기존 입력값으로 유지되며 새 기상청 순간 일사 관측으로 주장하지 않는다. 원래14시간 결과물과 기존 릴리스 증거는 변경하지 않았다.
