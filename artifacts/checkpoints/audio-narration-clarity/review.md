# 쉬운 한국어 내레이션 후보 비교 (준비 전용)

기존1.7 리허설 원고의 영향7문장만 Yuna170으로 별도 합성했다. 원본 영상/원고/제작코드는 변경하지 않았다. 같은 고정 whisper.cpp/small 모델, ko, CPU4threads, prompt 없음으로 전사했다. 각 문장 PCM 뒤1초 무음을 넣은 새 결합 PCM만 사용했다. 직접 청취false이며 최종 녹화용 음성이 아니다.

실제 인식에서 ‘측정한 값’, ‘마지막으로 받은 결과’, ‘메시지 아이디’, ‘구조화된 파일’, ‘재현에 쓰는 초기 값’, ‘다시 불러오면 새 실행 아이디’, ‘메시지 형식’이 모두 나타난다. 원래 ASR의 해당 난해한 인식 불일치는 이번 후보 전사에서는 나타나지 않았다. 다만 이는 모델의 텍스트 인식 결과이며 원래 발음 오류나 후보의 자연스러운 발음을 입증하지 않는다. ‘시험→실험’, ‘있으므로→있음으로’, 조사/띄어쓰기 차이는 남는다.

뜻의 핵심 범위는 현재 선택한 단지/발전기, 서버 저장 상태 재조회, 중복 가능성과 아이디, 최대20개 저장 상태, 재현 조건, 선택RTU/새 실행아이디, RTU토픽/메시지형식이다. 접수≠완료·기존outbox유지·외부VPP/전체감사 아님은 변경하지 않는 주변 원고가 유지한다.

정밀도 검토: ‘구조화된 파일’만으로 JSON을 특정할 수 없으므로 화면/자막 설명·PPT에서 JSON 형식을 유지해야 한다. ‘재현에 쓰는 초기값’은 난수 의미를 생략하므로 seed UI/기술 문서의 정확한 정의가 유지되어야 한다. ‘선택한 RTU의 저장한 시나리오’는 문법상 어색하므로 채택 전에 메인이 문장을 다듬는 것이 좋다. 이 후보를 코드에 적용하지 않았으며 더 다듬은 문장은 최종 새 음성에서 다시 검수한다.

정확한 원고/후보/scene·cue/시각/문장별 해시/실제 전사/옵션은 comparison.json과 원본 ASR 파일에 있다. 기존 ASR 및 기술검수 근거는 불변이다.
