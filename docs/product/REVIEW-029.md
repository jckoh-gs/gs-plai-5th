# 제품 검토 029 — IDEA010 제안: 운영 이벤트의 실제 시각 표시

**미채택 제안이다.** 기능 추가 수량을 목표로 삼지 않고 소스에서 발견한 작고 구체적인 진단 공백 하나만 제안한다. 현재 stable1.5와 원래 동결21:37:33Z/종료22:07:33Z, 최종 영상·PPT 조건은 유지한다.

server/store.js의 audit_events는 created 열에 UTC ISO를 저장하고 events()는 id/created/level/message를 그대로 최근80개 반환한다. server/index.js의 /state·SSE는 그 배열을 사용한다. 반면 web/src.jsx의 Logs 시각 셀은 timestamp 또는 createdAt 또는 time만 조회하고 **created를 읽지 않는다**. 실제 저장된 시각이 화면의 time formatter로 전달되지 않는 소스 계약 불일치다. 기존 browser-api-guide는 이벤트 메시지 포함과 Invalid Date 부재를 확인하지만 실제 created 시각의 일치를 검증하지 않는다. 따라서 과거 로그 화면 PASS를 실제 시각 정확성 증거로 확대하면 안 된다. 이번에는 브라우저에서 새 재현이나 운영 쓰기를 하지 않았으므로 소스 관찰로 구분한다.

사용자 효용: 연결 실패·명령·시나리오 사건을 대조할 때 실제 발생 순서뿐 아니라 저장된 UTC 시각을 확인할 수 있어야 한다. 명령 receipt/최근명령 export와 달리 운영 audit_events의 시각에 관한 문제이므로 IDEA006/009와 중복되지 않는다.

최소 권고 범위는 기존 이벤트 표의 실제 created 필드 표시와 표시 시간대 안내다. 서버·DB·API 계약/과거 데이터/정렬을 바꾸지 않는다. 새필터·export·검색·페이지네이션·대규모 로그 화면 재설계는 추가하지 않는다. 원본 ISO를 title 또는 접근 가능한 보조 문구로 보여주는 선택은 가능하나 임의 현재시각 대입은 금지한다. 유효하지 않거나 누락된 시각은 명확한 대시/미확인으로 남긴다. 현재80개 최근기록이라는 범위는 유지한다.

수락 제안:

- 기존 실제 /state 이벤트의 created와 화면 표시를 한국시간 또는 명시한 시간대 기준으로 정확히 대조한다. 최소2개 서로다른 시각과 날짜 경계 fixture를 검사한다.
- 실제 created만 있는 행이 비어 있지 않고 현재 시간으로 대체되지 않는다. malformed/누락 값은 Invalid Date 또는 가짜 시각을 보여주지 않는다.
- 메시지·유형·id내림차순·최대80개 계약이 바뀌지 않는다. 이벤트 저장·재전송·제어 명령을 생성하지 않는다.
- 한글/좁은 화면/접근 가능한 시각 정보와 기존 가이드·로그 비밀 비노출 회귀를 확인한다. 새 라이브 사건을 만들 필요 없이 기존 이벤트의 읽기 대조와 격리 fixture로 검증한다.
- 채택 시 수정된 실제 이미지의 원격 로그 시각 대조와 기존 릴리스/복원 게이트를 거쳐야 하며 로컬 CSS/파일 존재만으로 완료하지 않는다.

권고: 실제 읽기 재현을 독립 이슈 담당이 확인하면 작은 결함 수정으로 채택할 가치가 있다. 채택 전 버전 배정은 하지 않으며, 채택할 경우 기존 정책에 따라 PRD/제품 다음 minor에 변경 이유와 수락 조건을 기록한다. 새 인프라·OSS·DB마이그레이션 위험은 없지만 시간대 표시의 혼동과 역사적 인수 주장의 과장이 주요 위험이다.1.5 불변 체크포인트를 수정하지 않는다.
