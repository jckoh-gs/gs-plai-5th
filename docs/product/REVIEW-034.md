# 제품 검토 034 — IDEA011 제안: 명령 목록 조회 실패의 가시성

미채택 제안이다. 실제main1.6의 기존3104접속에서 GET만 허용하고 기존 명령이있는 RTU의 명령처리결과를 읽었다. 이어 브라우저에서 해당 GET commands만503으로응답시키는통제fixture를 적용했다. 원격서버의 실제장애를 만들지 않았고 API쓰기0,관측GET실패2회였다. 결과와 재현소스는 artifacts/checkpoints/command-list-readonly-before에 보존했다.

실제 before/after 명령표는완전히같고 조회오류안내가없으며 상단은“실시간 연결”이었다. web/src.jsx Commands는 poll catch에서error를저장하지만 rows가비어있을때만 error를렌더한다. 따라서 이전성공행이있으면 후속목록조회실패가숨겨진다. globalSSE의정상표시는 별도스트림이라 명령목록신선도의증거가아니다. 이는극단입력이아니라조회한개가실패하는일반재접속상황에서운영자가오래된명령상태를새상태로해석할수있는공백이다.

IDEA003은전체state/SSE 지연,IDEA009는이탭의POSTreceipt와개별ID확인이다. 본제안은REST/MQTT출처를포함한서버최근명령표의독립GET신선도이므로중복되지않는다.

최소범위는 Commands 표에최근성공조회시각/조회실패표시를항상보여주고 기존행을“마지막확인값”으로보존하는것이다. 최초조회중/성공빈목록/오류를구분한다. RTU변경시이전목록·시각·오류가혼입되지않고재연결후성공하면경고를해제한다. 필요하면이미있는2초poll을중복없이사용하며새POST·재전송·DB/API·수동제어·필터/export추가는하지않는다. 무한대기와동시poll누적을방지하는유한요청수명은구현시최소범위로검토하되일반fetch전체재설계는제외한다.

수락안: 실제기존행확보→GET만실패시이전행유지+명시적갱신실패/마지막성공시각;다시성공시경고해제·새상태갱신;처음부터실패와실제빈목록구분;SSE정상이어도로컬목록실패가보임;A지연중B선택후늦은A불혼입;키보드/좁은화면;자동POST0/중복조회없음. 실제원격읽기+격리응답fixture를구분하고이전테스트를반복합산하지않는다. 최종후보배포·복원게이트는그대로다.
