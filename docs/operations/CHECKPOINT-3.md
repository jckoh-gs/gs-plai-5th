# 정상 실행 체크포인트 3

제품1.2.0 / PRD1.9 / 런타임 소스 `83d10cebcd7cab2b1f889c970011a463bad09099`. IDEA-006은 선택 RTU의 최근 갱신 순 최대20개 저장 명령 상태를 JSON으로 내려받는다. 원본 요청·자유문자열 사유·CSV는 제외하며 알려진 비밀값과 인증 URL을 정제한다. 전체 수신 이력이나 외부 VPP 수신 증거, 재발행용 명령 파일은 아니다.

앱 이미지 `sha256:cc387c6db005acf798dbbbbd41979f07114474a5fe697118ad8c29afc904eab6`는 격리한 정확한 소스에서 빌드했다. 로컬88개 시험은 앱79개와 워크스테이션 운영9개를 포함한다. 정확한 Linux 이미지에서 앱79개 및 실제 MQTT 통합·고급 장애 시험이 통과했다. 새 의존성은 없다. 이미지의 미수정 매치4개에는 현재 피드의 수정 버전이 없으며 취약점 관리 문서에 유지한다.

실제 k3s에서는 인증 UI/SSE/연결 단절 표시·복구/좁은 화면, CSV 미리보기, RTU별 실제 JSON 다운로드·401 실패 처리를 확인했다. MQTT 목표125kW, 실제125kW, 오차0, accepted/executing/completed, 같은 명령 중복 제거, 60개 전체 SCADA 샘플을 검증했다. 실제 Pod 교체 후 outbox 메시지의 ID·순서·본문이 같고 MQTT 재수신과 PUBACK 저장까지 통과했다.

정상 백업은 `deploy/verification/stable-backup-83d10ce.json`에 기록한다. 169414656바이트, SHA256 `805040d3897b7f71ca1f718e58729dbe49ec512e610c1fc79e053b58d3916c88`이며22개 전송 청크·전체 해시·SQLite 무결성을 검증했다. 새 격리 PVC의1.2복원에서 원본5단지/runId/발전기ID/행 수/시나리오와 UI·명령 다운로드·실제MQTT 검증을 통과했다. 같은 DB의 이전1.1버전에서도 원본 데이터·인증 UI/SSE·미리보기·실제 MQTT를 검증했다. 복구 rig는0개이며 Pod 종료와 소유 터널 종료를 확인했다. 정상 태그는 `stable-v1.2.0`과 동일 커밋의 별칭 `stable-runtime-v1.2.0-83d10ce`다.

1.1관측 기록에는 로컬 네트워크 단절로 인한 실제 관찰 공백과246연결 오류·44API 오류가 남아 있다. 원격 서비스가 중단되었다거나 관측이 무중단이었다고 해석하지 않는다. `artifacts/checkpoints/soak-1.1.0/`과 ISSUE-014에서 확인한다.1.2관찰은 별도 세션이며 이전 기록을 초기화하거나 덮어쓰지 않았다. 자동 연결 감독기는 실제 이미지·API·MQTT를 다시 확인하고 원래 마감을 지킨다.

전체 목표는 진행 중이다. 최종30분에 확정 버전의 새 영상과 후속 PPT를 제작·검수해야 하며 리허설 산출물은 최종 인도가 아니다.
