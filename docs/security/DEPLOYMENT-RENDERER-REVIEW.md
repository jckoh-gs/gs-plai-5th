# Deployment renderer operational correction

The wrapper previously replaced GRID_IMAGE with sed, but a pinned app image contained no placeholder, silently ignoring the supplied new image argument. Actual1.7 rollout was performed independently and is not re-executed by this correction.

A pure dependency-free renderer now validates exact app/broker repository references and64 lowercase digest hex digits; it rejects newlines and shell/sed metacharacters. It replaces the unique app container and both broker migration-init/runtime container image slots whether their old values are valid pins or placeholders. Missing, duplicate, wrong, unexpected-image or unsupported-format slots fail before stdout/apply. The parser deliberately supports only this canonical checked-in indentation/name/image layout, not arbitrary YAML. Broader YAML edits must update/review the renderer instead of bypassing its guard.

The shell wrapper runs from the repository root, uses its fixed deploy/app.yaml path, renders into a unique mode-private temporary file, and applies only after successful rendering. Exit cleanup removes only that owned temporary file. Render-only CLI is separate and does not invoke kubectl. The app template pin is updated to currentd1e4 at root's request; passed validated images remain authoritative for deployment or rollback. Existing migration command/volume/network policies are unchanged.

Three meaningful pure tests pass: pinned and placeholder replacement including both broker slots; invalid digest/newline/metacharacter rejection; malformed/missing/duplicate slots and stray images rejected. Shell syntax check passes. Hashes/logs are in evidence/deployment-renderer-review.json and deployment-renderer-tests.log. No packages, runtime image, ledger, deployment object or remote execution was changed; no actual deployment result is claimed from these tests.

Root follow-up: six focused cases now include the shell wrapper, supplied-image authority with mode0600, no kubectl call on invalid input, apply failure stopping rollout, and owned temporary-file cleanup on both success and failure.
